# 검증 하네스

하네스는 에이전트가 작업을 반복해도 요구사항·테스트·배포 증거를 잃지 않게 하는 실행 체계다. 테스트 파일 존재만으로 검증 완료라고 기록하지 않는다.

## 현재 구현된 최소 단계

소스 저장소에서 Node.js 22 이상으로 실행한다. 외부 패키지 설치나 비밀 값이 필요 없다.

```sh
node --test
node scripts/validate-catalog.mjs path/to/catalog.json
```

계약 테스트는 중복 ID, 잘못된 가수 참조, 번호 상태 모순, 중복 업체 번호, 날짜/출처 오류, unknown과 unlisted 차이를 검증한다. 테스트 픽스처는 합성 자료이며 운영 데이터가 아니다. CLI는 실제 입력을 검증하고 잘못된 데이터에서 0이 아닌 종료 코드를 반환한다. 빈 카탈로그도 거부한다.

GitHub Actions의 contracts 잡으로 같은 명령을 실행한다. CI가 실행되지 않으면 통과로 기록하지 않는다. 원본 데이터 이관 전에는 이 테스트가 운영 데이터를 검증한 것이 아니다.

## 앱 이관 후 추가할 검증

| 단계 | 검증 | 실패 시 |
| --- | --- | --- |
| 원본 기준선 | package/lockfile·빌드·라우트·데이터 수·저장 키 | 이관 완료 선언 금지 |
| 데이터 | 계약·정정 목록·스냅샷 변화·출처 | 기존 정상 데이터 유지 |
| 단위 | 검색 우선순위·정규화·저장 이관·차트 장애 | 수정 후 관련 테스트 |
| 빌드 | 정적 출력·고유 제목·canonical·링크·404·robots/sitemap | 배포 제외 |
| E2E | 검색→상세→복사→저장→재방문, 필터 URL, 모바일 | 미리보기 수정 |
| 접근성 | 키보드·포커스·상태 알림·자동 검사 | 주요 위반 수정 |
| 성능 | 같은 조건 전후 지표와 번들/색인 크기 | 회귀 근거 기록 |
| 운영 | 정확한 SHA의 미리보기·실서비스·복구 | 마지막 정상 버전 복구 |

브라우저 도구가 있으면 사용하고 없으면 Playwright를 사용한 이유를 기록한다. 현재 실행기 실패로 두 방식 모두 실행할 수 없는 상태다.

## 완료 증거

Issue/PR에 기준 스펙 ID, 변경 SHA, 실행한 명령과 결과, 미리보기 URL, 스크린샷/로그 위치, 데이터 변경 요약, 남은 제약을 기록한다. 실패를 지우기 위한 무조건 재실행·테스트 약화는 하지 않는다. 영향이 작은 문서 변경에 의미 없는 테스트를 추가하지 않는다.
