10개 브라우저 흐름은 느린 catalog 준비, 복합 검색/번호 조건/URL/뒤로가기, 이전 .html/query/hash 주소, 기존 문자열·객체·미해결 저장 항목, 손상 JSON 원본 보존, 읽기 성공/쓰기 거부의 탭 이동 복원, clipboard 거부 대체와 unknown 복사 없음, JS 없는 본문/보관 ID, 모바일 키보드/overflow, 실제404/비공개 경계다.

Browser plugin이 없어 Playwright를 사용했다. 로컬 원격 Chromium의 TLS 신뢰가 현재 세션 proxy CA와 맞지 않았고 영구 NSS 신뢰 변경은 자동 승인 검토가 지속 인증서 신뢰 변경을 이유로 거부해 실행하지 않았다. 기존 신뢰를 사용하는 APIRequestContext와 정상 HTTPS GitHub runner에서 검증을 완료했다. TLS 검증 해제·정책 우회는 사용하지 않았다.

## 복구 범위

복구 시험에는 같은 source279cc3e의 두 성공 artifact를 전용 noindex preview 프로젝트에 사용했다. 두 번째 배포32e9c9c7-73f9-43ff-9b47-f6ad8f98bf3c에서 첫 배포363bb785-5d9f-43af-955e-452c153fdd1e로 실제 POST rollback을 실행했고 GET으로 canonical ID를 대조했다. 이후 stable alias의 metadata·catalog hash·경로·헤더·404를 다시 확인했다. 기존 운영 todayjpop의 rollback 실행·권한·도메인 전환으로 확대하지 않는다.
