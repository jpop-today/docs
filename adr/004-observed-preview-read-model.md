# ADR-004: 관측 번호 앱 미리보기와 검증 데이터의 분리

2026-10-13 KST · accepted · DATA-001, SEARCH-001, SONG-001, FAVORITES-001, RELEASE-001. 작업: [소스 Issue#5](https://github.com/jpop-today/jpoptoday/issues/5).

기존 staging 3,317개 ID에는 운영 목록의 번호 관측값이 있고 행별 공식 확인 근거는 없다. 검증 계약 v1의 registered로 일괄 변환하면 사실이 달라진다. 반대로 앱 구현을 모든 행의 재대조까지 미루면 검색·URL·저장 이관을 검증할 수 없다.

새 Astro 앱은 별도 공개 read model을 만든다. staging을 검증하고 ID·원제·한글명·가수·태그·사업자 관측 번호·현재/보관 상태만 선택한다. observed-unverified는 그대로 유지하며 번호 옆 설명과 상세 본문에 재확인 필요를 표시한다. unknown은 확인 필요로 표시하고 복사 기능을 제공하지 않는다. 원본 refs/hash/가사/이미지/내부 진단은 공개 payload에 넣지 않는다. 공식 대조 전 공유 번호 후보는 자동 합치지 않고 번호 충돌 안내와 공식 검색 경로를 제공한다.

관측 read model은 검증 카탈로그 v1이 아니고 기존 승격 스크립트 입력으로 사용하지 않는다. 번호 확인일을 빌드일·import일로 만들지 않는다. 현재 스냅샷의 실제 원본 revision은 내부 build manifest에 연결한다. 이전 차트 보관 ID는 URL·저장 복구를 위해 상세에서 유지하되 기본 검색에서 제외한다.

첫 배포는 별도 Cloudflare 미리보기 프로젝트이며 모든 페이지를 noindex로 둔다. 검색·곡 상세·즐겨찾기·가이드·404·비공개 경계와 rollback을 실제 확인한다. 운영 전환은 기존 URL/가이드/차트 유지, 내용 검토와 문의/개인정보, 동일 SHA CI/preview 및 복구 게이트를 만족한 후 진행한다. 미리보기 완료로 운영 전환·검색 색인·AdSense 신청 가능을 표시하지 않는다.

대안: v1 근거를 임의 생성하는 것은 거부한다. 합성 fixture 공개는 실제 사용자 자료의 회귀를 검증하지 못한다. 기존 운영 번호를 확인 완료로 그대로 복제하는 것도 거부한다. 기존 관측값을 정확히 설명하는 미리보기로 UI 이관을 검증하면서 공식 근거 작업을 병행한다.

검증: 3,317 ID roundtrip, 숫자 문자열 보존, unknown 복사 없음, 공유번호 경고, archived 검색 제외/상세 유지, JS 없는 정적 상세, 공개 artifact의 raw/가사/외부이미지 제외, 미리보기 noindex, 기존 storage 읽기·실패 보존, 실제 404.
