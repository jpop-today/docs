# ADR-005 · 매일 세 에이전트 개발과 근거 기반 보고

상태: accepted · 2026-10-13 KST · DAILY-001, REPORT-001, TEAM-001, DESIGN-001, RELEASE-001 · jpoptoday#9.

## 문제

운영자는 매일 09:00 한국 시간에 관리자와 새 하위 에이전트 세 명이 개발하고, 두 동료의 평가로 최저 품질 담당을 교체하며, Discord와 채팅에 전일/계획·검증된 개선·버전 릴리스를 보고하도록 위임했다. 기존 원본의 그라데이션도 유지하도록 지정했다. 하나의 클라우드 세션을 계속 켜 두는 방식은 실행 이력·검증·재개를 보장하지 않는다.

## 결정

Codex의 실제 일일 예약은 관리자의 개발 실행을 시작한다. GitHub Actions의 UTC00:00 cron은 저장된 전날 결과·오늘 계획을 보고하며 CI/CD와 릴리스 알림도 담당한다. Actions 보고를 AI 개발 실행으로 설명하지 않는다. 오전 Discord는 Actions를 기본 발송 경로로 사용하고, 관리자는 같은 보고를 채팅에 남긴다. 변경된 배정·차단 등 추가 내용만 관리자 메시지로 보낸다. 같은 완료 알림의 기존 성공 이력을 확인한 후 수동 재발송한다.

각 실행은 새로운 세 담당과 겹치지 않는 파일 계약으로 시작한다. 공용 파일·Git·검증·배포는 관리자가 통합한다. 각 결과에 나머지 두 담당이 정확성·증거·사용자 가치·유지보수성의 0..5 점수와 실제 근거를 제출한다. 총6개 리뷰와 관리자 검증 후 최저 두 리뷰 합을 교체 기준으로 사용한다. 물리 삭제 도구가 없으므로 active roster 제외·interrupt·새 spawn으로 교체하고 결과와 평가 이력을 보존한다. 다음 날은 다시 새 세 담당으로 시작한다.

Discord는 DISCORD_WEBHOOK_URL Secret을 송신 단계에만 제공하고 trusted main 송신기를 사용한다. 누락은 skipped, 실패는 failed, HTTP 성공만 sent다. 실제 전날 기록이 없는 날은 그 사실을 보고한다. 승인·배포·개선·동료 점수를 만들어내지 않는다. 버전은 의미 있는 검증된 변경에만 올리고 태그의 버전·main 이력·노트·계약/타입/artifact/Chromium 검증을 통과한 후 GitHub Release로 게시한다.

디자인은 원본 CSS의 실제 파랑·분홍 브랜드와 body의 파스텔 그라데이션을 사용한다. 기존 흰색/크림슨 콘셉트의 색상은 이번 명시 사용자 요청으로 대체한다. 본문·링크·버튼 대비와 기존 검색/저장 흐름을 확인한다.

## 대안과 결과

단일 무기한 세션, GitHub cron만으로 AI 개발을 수행했다고 주장하는 방식, 출력 분량으로 순위를 정하는 방식은 요구의 실제 실행·품질 근거를 충족하지 못한다. 기록·예약·CI를 분리하면 환경이나 계정 단계가 막혀도 독립적인 작업을 이어갈 수 있다. 큐 지연·권한·실행 환경 제한은 실제 관측 결과로 남기며 정시·24시간 실행을 보장하지 않는다.

## 검증

[일일 운영](../operations/daily-development.md), 소스 scripts/build-report.mjs·discord-notify.mjs와 테스트, 실제 예약 조회·GitHub CI/Release·미리보기 기록을 기준으로 확인한다. 설계 승인과 실제 실행·Google 승인은 다른 상태다.
