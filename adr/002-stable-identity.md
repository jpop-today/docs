# ADR-002: 곡의 영속 ID와 이전 식별자

2026-10-13 · accepted · DATA-001, SONG-001, FAVORITES-001.

원본 등록 ID는 title|artist|TJ|KY 해시에 의존한다. 번호나 표기를 정정하면 ID가 바뀌어 공유 URL과 즐겨찾기가 끊길 수 있다. dev/main의 공개 카탈로그 ID 합집합은 실측 3,317개이며 실제 운영 SHA가 다르면 추가 ID가 있을 수 있다.

기존 ID를 영속 ID의 초기값으로 고정하고 이후 편집값에서 ID를 재계산하지 않는다. 동일 곡의 이전 ID는 alias→canonical으로 명시한다. 신규 곡은 변경될 제목·번호와 독립된 ID를 부여한다. 충돌·동명이곡·다른 버전은 자동 합치지 않고 검토한다.

번호만을 ID로 쓰는 대안은 사업자별 다른 번호·버전·충돌을 설명하지 못하므로 배제한다. 제목 정규화만으로 합치는 것도 배제한다. 앨범/버전 근거가 없으면 동일 곡 판정을 보류한다.

기존 /song?id=와 jpop_today_favorites key를 유지하는 어댑터를 제공한다. 문자열 배열과 {id} 입력을 읽고 미해결 ID는 보존한다. localStorage 이관은 원본 읽기→정상 파싱→alias 해결→검증→저장 순서로 하며 실패하면 기존 바이트를 보존한다.

검증: 번호/표기 정정 전후 identity 같음, 두 원본 SHA의 ID fixture, query URL 연결, 미해결·깨진 저장값·storage 접근 실패·뒤로가기·다른 기기 제한 안내. 이전 fragment route도 유지한다.
